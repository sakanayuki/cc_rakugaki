# らくがきバトル

2Dでお絵かきしたキャラクターが3Dで動き出し、NPCと連戦して**5連勝**を目指すWebアプリ。

公開URL: https://sakanayuki.github.io/cc_rakugaki/

設計の詳細は [DESIGN.md](./DESIGN.md) を参照。

## あそびかた

1. **メインメニュー** — あたらしく はじめる／つづきから を選ぶ
2. **オエカキ** — からだ → あたま → りょううで → りょうあし の4ステップで描く
3. **動作プレビュー** — 絵から自動でリグが組まれ、4つのアクションとステータスを確認する
4. **ルーレット** — 6種類の敵から対戦相手を抽選する
5. **戦闘** — 自動で戦う。3往復して決着がつかないと必殺技が使える
6. **リザルト** — 勝つと全ステータスが1.5倍。5連勝で優勝

## 絵からステータスが決まるルール

| パーツ | 影響するもの | ルール |
| --- | --- | --- |
| からだ | ❤️ たいりょく | 塗った面積が広いほど高い（60〜150） |
| りょううで | 💪 こうげき | 塗った面積が広いほど高い（10〜40） |
| りょうあし | 👟 はやさ | 塗った面積が広いほど高い（5〜25） |
| あたま | 属性 | 形で決まる（下記） |

属性は**あたまの形**だけで決まり、じゃんけんと同じ三すくみになる。

- 細長い（縦横比 1.5以上 または 0.67以下） → ✌️ チョキ（ざんげき）
- まるくて塗り密度が高い（0.5以上） → ✊ グー（どんき）
- それ以外 → 🖐 パー（とびどうぐ）

相性は グー→チョキ、チョキ→パー、パー→グー が2倍、逆は0.5倍。

さらに、使ったパレット色の種類数に応じて全ステータスに最大+10%のボーナスがつく。

## 開発

```bash
npm install
npm run dev      # 開発サーバー
npm test         # ロジックの単体テスト（Vitest）
npm run build    # 型チェック + 本番ビルド（dist/）
npm run preview  # ビルド結果の確認
```

### 技術スタック

- TypeScript（strict）+ Vite
- Three.js — ペーパークラフト風の3D表示。描いたパーツをテクスチャ付き板ポリゴンにして関節で回す
- Canvas 2D API — お絵かき（ライブラリ不使用）
- Web Audio API — 効果音をその場で合成（音声ファイルなし）
- localStorage — 絵のセーブ（1スロット）

外部CDN・外部フォント・外部APIは使わないため、初回ロード後はオフラインでも動作する。

### 設計上のポイント

- **絵はベクタで保持** — ビットマップではなく描画オペレーション列（`DrawOp[]`）。
  undo・パーツやり直し・保存/復元がすべて「オペを消して再生し直す」だけで成立する。
- **塗りつぶしの境界は全レイヤーの合成画像** — からだの輪郭を境界にして、うでレイヤーを塗れる。
  そのため再生は必ず全パーツ横断で `seq` 順に行う。
- **ロジックはDOM非依存** — `src/game/` と `src/paint/floodFill.ts` は
  Three.jsもDOMも参照しないので、Vitestでそのまま検証できる。
- **敵もプレイヤーと同じデータ形式** — 敵6種の見た目は `CharacterDoc`（描画オペレーション列）
  として定義してあり、リグ生成・アニメーションのパイプラインを完全に共通化している。

## デプロイ

`main` ブランチへの push で GitHub Actions が起動し、テスト → ビルド → GitHub Pages への
デプロイまで自動で走る（`.github/workflows/deploy.yml`）。

初回のみ、リポジトリ設定で **Settings → Pages → Source** を **GitHub Actions** に
変更しておく必要がある。

公開URLがリポジトリ名のサブパス配下になるため、`vite.config.ts` の
`base: '/cc_rakugaki/'` は必須。これを外すと本番でアセットが404になる。
